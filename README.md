## 1. 이기종 뇌파 데이터 통합과 분류 모델 (석사 연구, 인하대학교)

저장 형식이 다른 공개 데이터셋 3종을 Python 전처리 파이프라인으로 통합했습니다.

- pkl 파일: 배열 결합과 shape 오류 수정
- 채널 신호: 채널별 전압 오프셋 보정
- .mat 형식의 데이터셋 추가: 라벨 매핑, 전압 단위(V에서 µV), 밀리초와 샘플 인덱스 변환 오류 수정
- 메모리: 피험자 단위로 나눠 불러와 15GB RAM에서 학습, 변환 코드는 GitHub에 공개

시간, 시간-주파수, 공간 정보를 각각 처리하는 세 갈래 분류 모델을 공개 데이터셋 3종으로 설계했습니다.
학습에 쓰지 않은 피험자 기준(LOSO)으로 기존 모델 대비 정확도 7.61%p 개선을 Wilcoxon 검정과 Holm 보정으로 확인했고, 의공학회지 47(2):95-101, 2026에 제1저자로 게재했습니다.

## 2. 수집 중에 이상을 잡는 센서 실험 앱 (인하대학교, 3인 팀)

3인 팀에서 실험 설계와 데이터 수집을 맡았습니다. IRB 승인을 받은 28명 대상 실험에 쓸 Android 수집 앱을 Kotlin으로 개발했습니다.

- 첫 참가자로 직접 실험하다 센서 신호가 순간적으로 0이 되는 구간을 발견했고, 손목 움직임과 그립이 풀리는 시점과 겹침을 확인했습니다.
- 팀 논의를 거쳐 이런 구간을 감지하면 즉시 중단하고 직전 데이터를 자동 저장한 뒤 이어서 진행하도록 구현했습니다.
- 처음부터 다시 해야 했을 중단 3회를 모두 그날 이어서 진행했고, 새 일정으로 재실험한 사람은 장치 연결이 끊긴 2명이었습니다.
- 여유 기간을 포함해 4주로 계획한 실험을 2주 만에 마쳤습니다.

## 3. SQL로 오류가 들어온 적재 차수 추적 (개인 프로젝트, MySQL)

기존에 쓰던 일정 앱에서 세 차례에 나눠 옮긴 일정 1,555건을 MySQL에 적재해 점검했습니다.

- 중복: COUNT(DISTINCT)와 GROUP BY를 교차 집계해 NULL 행이 빠진 오집계를 바로잡고 506건으로 확정
- 시간대: 제목의 시각을 정답지로 삼아 50개를 비교했고, 한국 시각이 UTC로 잘못 변환된 45개가 1차와 3차 적재에만 존재
- 혼입: 일정이 아닌 가계부 24건과 일기 21건이 섞여 들어온 것을 확인
- 종일 일정: 09:00 시작의 여러 날 일정으로 바뀐 문제는 가져오기 코드를 수정

## 4. LLM 일정 앱과 MCP 서버 (개인 프로젝트, 지인 5명에게 배포)

문장을 일정으로 바꾸는 앱을 LLM API로 만들어 지인 5명에게 배포했습니다.

- 구조: 사용자 문장, LLM API(응답 실패 시 3단계 폴백), 필드 검사, 등록 단계(제목, 날짜, 시작 시각이 같으면 중복으로 거름), 일정 DB
- 형식은 맞지만 틀린 날짜: 크리스마스 주간(정답 21~27일)을 18~24일로 반환해도 필드 검사를 통과해 저장됨
- MCP 서버: 조회와 등록만 허용해 기존 일정의 수정과 삭제는 막았지만, 틀린 값의 등록은 막지 못함

직접 정답을 붙인 127문장 평가셋의 첫 점수는 26%였습니다. 원인은 정답 표기 오류, 평가 도구 캐시, 무응답 계산 방식이었고, 이미 본 문장을 버리고 새 문장으로 다시 측정했습니다.

## 5. ROS2 협동로봇 통신 장애의 원인 분리 (WISET 120시간 과정, 한양대학교 ERICA, 2026.06.15~07.16)

Ubuntu PC 여러 대에서 협동로봇 7대를 운용하던 중, 한 로봇의 명령을 다른 로봇이 실행해 사람과 부딪힐 뻔했습니다.

- 원인 추적: IP 충돌을 먼저 배제했고, 모든 PC가 같은 ROS_DOMAIN_ID와 Namespace를 써 노드가 서로 보인 것을 원인으로 특정
- 조치: PC별로 ROS_DOMAIN_ID를 분리하고, 로봇별로 Host IP를 분리
